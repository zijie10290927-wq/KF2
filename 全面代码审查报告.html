🔴 一、Blocker 级问题（必须修复）
🔴 已修复 B1 注册接口匿名提权为管理员 schemas/auth.py:21 · services/auth_service.py:253 ✔ commit 5aded41

/auth/register 在 JWT 白名单中（匿名可访问），而 RegisterRequest.role 允许传 admin，服务端无条件接受 → 任何人可注册管理员账号，控制知识库、渠道密钥、用户管理等全部管理功能。

修复：Schema pattern 收紧为 ^user$ + 服务端强制 role="user"（双重防线），新增 6 个回归测试。
🔴 Blocker B2 内置 admin/demo 账号 = 永久后门 main.py:87-105 · auth_service.py:40-55,186 · deps.py:116-134

lifespan 无条件创建 admin/admin123（生产环境也创建）；login 在「DB 不可达 或查无此用户」时都降级匹配内置账号 → 即使删掉 DB 里的 admin 行，admin/admin123 仍永远可登录。

建议：APP_ENV=production 时禁止创建默认账号、禁止内置降级；降级条件收紧为「仅 DB 明确不可达」。
🔴 Blocker B3 全部默认密钥为公开占位符，无生产强制校验 config/settings.py:66,71,92,96

JWT_SECRET_KEY、CRYPTO_SECRET_KEY、WEBHOOK_HMAC_SECRET、OPENAI_COMPAT_API_KEY 默认值均为公开已知字符串。生产忘改 → JWT 可被伪造（叠加 B2 直接拿到 admin）、Webhook 可伪造（叠加 B4 形成 SSRF）。

建议：lifespan 启动时检测 APP_ENV=production 且密钥仍为占位值 → 启动失败（fail-fast）并打印缺失清单。
🔴 Blocker B4 GenericAdapter 回调地址 SSRF adapters/platforms/generic_adapter.py:136-180

callback_url 完全由请求方控制（来自 webhook metadata），服务端直接 POST 任意 URL。配合 B3（默认 HMAC 密钥公开可伪造签名），攻击者可让服务器扫描内网（127.0.0.1、169.254.169.254 云元数据、内网段）或对第三方系统发起恶意回调。

建议：校验 scheme ∈ {http,https}、host 非保留 IP/内网段；或域名白名单。
🔴 Blocker B5 切换/删除会话时未中止进行中的 SSE 流（竞态） stores/chat.ts:39-57,124-130

selectSession/createSession/deleteSession 均未调用 stopStreaming()。流式输出中切换会话：旧流持续向孤儿对象写入（内存/带宽浪费）、isStreaming 保持 true 导致新会话无法发消息且无提示、切回旧会话时未持久化的临时消息丢失。

建议：三处开头调用 stopStreaming()；更稳妥——sendMessage 捕获 sessionId，回调中校验 currentSessionId === sessionId 再写入；ChatView onUnmounted 中 abort。
🔴 Blocker B6 渠道/模型配置编辑保存会清空已有密钥 ChannelManagement.vue:435-457 · ModelConfig.vue:135-152

UI 提示「留空则不修改」，但前端打开编辑框即把 api_token/webhook_secret/app_key 置空，随后无条件整体提交 → 后端按值更新，线上密钥被清空。

建议：提交前剔除空字符串字段（Object.fromEntries(Object.entries(form).filter(([,v]) => v !== ''))）。
🔴 Blocker B7 fallback 字段绕过类型系统（as any 穿透 3 个文件） stores/chat.ts:105 · AssistantMessage.vue:17 · types/index.ts:36-46

ChatMessage 接口缺少 fallback 字段，导致 (aiMsg as any).fallback 跨 3 个文件传递。字段形状变化时类型系统完全无法兜底，静默 undefined。

建议：接口增加 fallback?: FallbackData | null，删除全部相关 as any。
